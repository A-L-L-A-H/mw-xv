# ADR 0007: AI Corporation Addon-First Architecture

- **Status:** Accepted (2026-11-22; autonomous approval under repository unconditional-autonomy governance)
- **Date:** 2026-11-22
- **Decision owners:** MoonWitness maintainers
- **Scope:** `@moonwitness/orm-ai`, `@moonwitness/ai-runtime`, `@moonwitness/ai-mcp`, `@moonwitness/ai-evaluation`, `apps/api`, `apps/board`
- **Related plan:** [`AI-CORPORATION-GRAND-PLAN.md`](../../moonwitness-ai-corporation-blueprint/docs/AI-CORPORATION-GRAND-PLAN.md)
- **Related tasks:** `M12.01`, `M12.02` (`AI1.1`–`AI1.25`)
- **Related decisions and policies:** [ADR 0001](0001-platform-contracts.md), [ADR 0004](0004-knowledge-rebuild-centralization.md), [ADR 0005](0005-mizan-evaluation-policy-boundary.md), [ADR 0006](0006-mandatory-addon-thin-api.md), [AI Corporation Baseline Audit](../architecture/ai-corporation-baseline-audit.md)

## Context

MoonWitness XV is a metadata-driven business platform built on `@moonwitness/orm` addons (`defineModel`, `defineAddon`, `installAddons`), PostgreSQL, Fastify (`apps/api`), Next.js (`apps/board`), `@moonwitness/jobs`, `@moonwitness/orm-workflow`, `@moonwitness/orm-organization`, `@moonwitness/orm-request`, `@moonwitness/orm-integration`, `@moonwitness/orm-storage`, `@moonwitness/orm-knowledge`, and an isolated K7 suggestion package (`@moonwitness/local-ai`).

Introducing an autonomous AI workforce ("AI Corporation" / EGAO) without an explicit architectural boundary risks creating a second source of truth, leaking generic CRUD mutations, elevating agent identities to `superadmin`/`system` privileges, or blurring K0–K9 source-grounded research boundaries with general tool-using execution. The baseline audit at `dev` (`43c3a43` -> `1c49cdd` -> `82e4f7c`) verified all 10 existing core domains and confirmed zero pre-existing AI Corporation runtime/ORM code.

## Decision

### 1. Core Architectural Principles (D1–D12, `AI1.13`)

1. **D1 — MoonWitness remains the source of truth:** All company, organization, work contract, agent, grant, policy, budget, approval, evidence-reference, and obligation state lives in MoonWitness domain models.
2. **D2 — ORM Addon-First remains mandatory (`AI1.14`):** Durable domain models, fields, relations, access metadata, views, menus, seeds, and upgrade hooks are declared through workspace addons (`defineModel`, `defineAddon`). No second ORM, parallel traditional SQL migration stream, or shadow business database is permitted.
3. **D3 — Reuse existing domain addons before creating new models:** `@moonwitness/orm-base`, `orm-organization`, `orm-workflow`, `orm-integration`, `orm-knowledge`, `orm-storage`, and `@moonwitness/jobs` remain authoritative for their domains.
4. **D4 — Knowledge AI and workforce AI remain separate boundaries:** `@moonwitness/local-ai` and K0–K9 remain isolated for loopback-only, tool-free research suggestions (`AI_MODE=disabled` default). General workforce execution lives in separate runtime packages.
5. **D5 — One bounded agent precedes the swarm:** Vertical slice v1 proves one bounded, read-only agent with durable job execution, evidence envelope, and independent verification before multi-agent orchestration.
6. **D6 — Acceptance is evidence-based (`BASE.29`):** Model self-reported completion never equates to verified acceptance; Proof-Carrying Work (PCW) requires verifiable evidence and independent review.
7. **D7 — Persistent obligation continuity ledger:** Accepted deliverables emit ongoing verification obligations tracked independently of request closure so future changes trigger impact analysis and selective re-verification.
8. **D8 — Adaptive workforce is bounded by a fixed constitution:** Temporary taskforces and delegations operate within explicit company scope, capability grants, risk tiers, depth limits, and budgets; agent workflows cannot alter their own authority or security policy.
9. **D9 — MCP and optional A2A remain stateless adapters (`AI1.17`):** MCP exposes authorized tools/resources via domain services and the capability gateway; any future A2A peer-agent protocol requires its own dedicated ADR before enablement.
10. **D10 — Learning changes are candidates first (`BASE.30`, `AI1.21`):** Episodic, semantic, and procedural memories/skills are persisted as unverified candidates requiring replay/ablation/harm evaluation and human approval before promotion.
11. **D11 — Existing `@moonwitness/jobs` is the initial durability layer (`AI1.9`):** Durable dispatch, `SKIP LOCKED` claiming, leases, heartbeats, fencing tokens, retries, dead-lettering, outbox, and cooperative `AbortSignal` cancellation use `@moonwitness/jobs` rather than a second queue database.
12. **D12 — Research claims remain evidence-bound:** Evaluation gates (`G0`–`G6`) measure verifiable capabilities, baselines, failed runs, and safety regressions without overclaiming AGI.

### 3. Work-Item Contract Decision (`BASE.27`, `AI1.4`)

Inspecting `packages/orm-request/src/models.ts:4-16` and `src/manifest.ts:46-53` showed `PurchaseRequest` carries only procurement fields (`title`, `description`, `amount_minor`, `currency`, `company`, `vendor`), has no service layer, and grants `base.group_user` generic `create`/`write` access. Extending `orm-request` with `request.work_item` would mix PCW governance fields (risk tier, acceptance criteria, verification digests, delegation depth, obligation links, capability grant) into a generic user-writable addon.

Therefore, **`@moonwitness/orm-request` remains unmodified**, and **`@moonwitness/orm-ai` owns `ai.work_contract` and `ai.acceptance_criterion`**, reusing `@moonwitness/orm-workflow` (`WorkflowInstance`) for lifecycle state transitions, independent reviewer enforcement (`requireDifferentActor: true`), and timeouts (`expireDueWorkflows`), with optional `(source_model, source_id)` correlation fields.

### 4. Agent Identity, Company Isolation & Capability Grants (`AI1.2`–`AI1.3`, `AI1.18`, `BASE.28`)

1. **Separately typed single-company identity (`AI1.2`):** An AI agent is modeled as `ai.agent` + `ai.agent_profile` in `@moonwitness/orm-ai`, linked to `@moonwitness/orm-organization` (`OrganizationDepartment`, `OrganizationTeam`, `OrganizationPosition`, and optionally `OrganizationMembership`).
2. **Prohibition of `superadmin`/`system` roles (`BASE.28`):** Because `apps/api/src/auth/policy.ts:52` and `apps/api/src/auth/rules.ts:44` grant `superadmin` and `system` full non-internal model access and bypass all row-level company rules (`return []`), an agent or its optional 1:1 service-principal `base.user` **MUST ONLY** carry `role: 'user'` — never `'superadmin'` or `'system'`.
3. **Immutable single-company isolation (`AI1.3`):** Every `ai.agent` has an immutable `company: belongsTo(Company, { required: true })`. Linked service-principal users may hold at most one `CompanyMembership` matching `agent.company_id`, and `x-company-id` cross-company switching is rejected for agent principals.
4. **Capability grants (`AI1.18`):** Authority is never derived from role names or prompt text. Every action requires an active `ai.capability_grant` specifying capability identifier (`<domain>.<action>@v<major>`), company/contract/run scope, `policy_version`, `expires_at`, and `revoked_at`. Grants are validated at dispatch **and re-checked at tool execution time**.

### 5. Ephemeral Data Outside ORM & Package Boundaries (`AI1.10`–`AI1.12`, `AI1.15`–`AI1.17`)

1. **Ephemeral / high-volume data outside ORM (`AI1.10`):** Streaming token chunks, raw provider HTTP payloads, transient chain-of-thought/step scratchpads, full model transcripts, large tool stdout/stderr, and high-frequency OTel traces/metrics are **never stored in ORM tables**. Compact checkpoint cursors and token/cost counters live on `ai.agent_run`; immutable transcripts/evidence blobs are written to `AttachmentStorage` (`@moonwitness/orm-storage`) and referenced by `ai.artifact_manifest` (`storage_key` UUID, `sha256`, `size_bytes`, retention TTL enforced via `reconcileAttachmentStorage` / `pruneOrphanAttachmentStorage`).
2. **Smallest viable package boundary (`AI1.11`–`AI1.12`):**
   - **Domain Plane — One cohesive ORM addon (`@moonwitness/orm-ai`):** Splitting durable AI models into multiple ORM addons lacks independent database/release lifecycles and fragments foreign keys, `API_ADDONS`, and `addon-conformance.test.mjs`. Unjustified micro-ORM splits are rejected.
   - **Execution Plane — Three non-ORM packages (`AI1.15`):**
     1. `@moonwitness/ai-runtime` (`packages/ai-runtime`): Separates **provider** (`AiProvider` transport: `MockProvider`, `OllamaAdapter`, `CloudProviderAdapter`), **model profile** (`ModelProfile` capabilities/limits), and **agent harness** (`AgentHarness` bounded loop/checkpointing) (`AI1.16`), plus `DataClassificationRouter`, capability/tool gateway, PCW verifier, workforce planner/delegation controller, memory/skill lifecycle, and GenAI telemetry.
     2. `@moonwitness/ai-mcp` (`packages/ai-mcp`): Stateless MCP server adapter delegating exclusively through `@moonwitness/ai-runtime` capability gateway and domain services (isolating MCP SDK dependencies; never accessing DB directly).
     3. `@moonwitness/ai-evaluation` (`packages/ai-evaluation`): Deterministic benchmark corpus, G0–G6 capability gates, memory ablation, and adversarial security harnesses (excluded from production API/worker runtime).
3. **Forbidden Addon-First Bypasses (`AI1.14`, ADR `0006`):**
   - `'ai.'` MUST be added to `INTERNAL_PREFIXES` in `apps/api/src/auth/policy.ts` to block unguarded generic REST (`/api/:model`) and JSON-RPC (`/jsonrpc`) mutations across all roles.
   - `@moonwitness/orm-ai` MUST be registered in `API_ADDONS` (`apps/api/src/addons/registry.ts`) and `scripts/roadmap/addon-conformance.test.mjs`, keeping `apps/api/src/app.ts` thin (`pnpm api:addon:check`).
   - All AI routes MUST reside in addon-registered Fastify plugins with explicit company scope and execution-time capability-grant checks.

### 6. Data Classification, PCW Verification, Memory Lifecycle & Threat Model (`AI1.19`–`AI1.24`)

1. **Data classification & routing (`AI1.19`):** Every work contract, artifact, and provider declares `local_only`, `cloud_eligible`, or `restricted`. `DataClassificationRouter` enforces fail-closed routing: `local_only` and `restricted` payloads never route or silently fall back to cloud providers. Authorization headers, `MW_AI_*` secrets, and sensitive errors are redacted from logs (`pino`) and diagnostics.
2. **PCW evidence, reviewer independence & risk tiers (`AI1.20`):** Risk tiers **R0** (read-only), **R1** (reversible internal candidate/artifact write), **R2** (scoped state transition / internal workflow), **R3** (external/high-impact effect requiring explicit human sign-off), and **R4** (prohibited in v1) govern execution. Acceptance requires verified evidence digests matching `ai.acceptance_criterion`, independent review (`WorkflowApproval` with `requireDifferentActor: true` and distinct `agent_id` / `run_id`), and human sign-off for configured tiers.
3. **Memory & skill lifecycle (`AI1.21`):** Agent experience is separated into episodic run records, semantic notes, and versioned procedural skills (`ai.memory_candidate`, `ai.skill_version`) — separate from K0–K9 authoritative knowledge. Retrieved memories are untrusted context only and can never grant authority. Promotion requires benchmark/ablation/harm evaluation and human/workflow approval; revocation blocks future run consumption immediately.
4. **Sandboxing & tool-execution threat model (`AI1.22`):** Repo files, web pages, issues, and tool outputs are untrusted data. Execution enforces explicit path allowlists, symlink/traversal rejection, bounded output/wall-clock/CPU/memory/quota caps, host-secret separation (no raw `process.env` leaks), default-deny network egress (SSRF-guarded via `orm-integration`), and audit logging of denied tool attempts.
5. **Compatibility, upgrade, rollback & deprecation (`AI1.23`):** `@moonwitness/orm-ai` uses additive-first `defineModel` schemas, chained semver `addon.upgrade[fromVersion]` hooks inside `db.transaction` (`pg_advisory_xact_lock`), edit-preserving `_orm_data` seeds, and `apps/api/src/commands/restore-drill-fixture.ts` backup/restore verification.
6. **Explicit v1 Non-Goals (`AI1.24`):**
   - No unrestricted OS shell, arbitrary filesystem write, or unallowlisted browser/network tool access.
   - No live autonomous self-modification of security policies, capability grants, prompts, or production code.
   - No unbudgeted open-ended multi-agent swarm or A2A external delegation without a dedicated A2A ADR.
   - No live cloud LLM API keys required for unit/integration/CI verification (cloud adapters are verified via deterministic mock/fixture contracts).
   - No staging/production application deployment (per [ADR 0001](0001-platform-contracts.md)).

## Consequences

- **Positive:** Preserves single source of truth in PostgreSQL/`@moonwitness/orm`, eliminates duplicated workflow/job/storage/organization engines, guarantees multi-tenant and privilege isolation, and keeps `apps/api` thin and auditable.
- **Costs / trade-offs:** Requires up-front schema/contract discipline across `@moonwitness/orm-ai` and `@moonwitness/ai-runtime`, independent verification overhead on R1–R3 tasks, and explicit cross-repo governance sync between `todo-ai-corporation.md` and `M12.01`–`M12.14`.
- **Review triggers:** Revisit this ADR if a dedicated A2A peer protocol is proposed (requires separate A2A ADR), if `@moonwitness/jobs` benchmarking uncovers hard durability limits, or if application deployment scope changes in an amendment to [ADR 0001](0001-platform-contracts.md).
