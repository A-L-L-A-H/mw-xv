# Project Charter — MoonWitness XV Visual Universe

## Product outcome

Evolve MoonWitness XV from a grunge/editorial web identity with manga artwork and UI micro-effects into a consistent, original anime-inspired visual universe. The universe must support reusable characters, environments, props, layered 2.5D scenes, animation clips, cinematic transitions, domain illustrations and optional soundscapes—while the operational product remains fast, accessible and trustworthy.

## Goals

1. A single visual language across the public experience and all user-facing addon domains.
2. A canonical, provenance-aware and buildable asset pack.
3. Reusable character/environment/scene production contracts.
4. A bounded scene runtime built on current dependencies where practical.
5. A Creative Lab integrated into the existing UI Catalog.
6. One production-quality immersive homepage scene as the first vertical slice.
7. Reusable asset coverage for all 12 active addon manifests.
8. Responsive, reduced-motion, offline/failure and static fallback behavior.

## Non-goals

- Rebuild the whole monorepo or ORM engine.
- Make every screen a game or animation.
- Add a new ORM addon for static artwork.
- Build a full 3D engine before a measured need exists.
- Add paid/proprietary animation SDKs without approval.
- Replace real app data with invented characters, stats or maps.
- Make all media editable from production UI in the first release.
- Create one new package per domain or addon.

## Experience tiers

1. **Living World** — Home, Signals, Archive, Crew and Stories: cinematic scenes, character/world atmosphere, deliberate animation.
2. **Editorial World** — public/auth/story surfaces: manga panels, zine collage, controlled motion, live text.
3. **Operational World** — Board, data forms, tables, workflows, notifications: readable, restrained, efficient; anime identity via materials, token accents and modest interactions.
4. **Infrastructure** — API/ORM/jobs/AI runtime: no visual or browser-media dependency.

## Success measures

- All active addon domains mapped to genuine product routes/views/states.
- Every shipped asset registered, traceable and package-exported correctly.
- Repeated character identity is consistent across approved scenes.
- Scene runtime has lifecycle, pause/resume, disposal, reduced-motion and static fallback.
- Homepage vertical slice meets agreed browser/device budgets.
- Existing Board operations, permission boundaries, data correctness, themes and accessibility remain intact.
- No unapproved third-party/proprietary art, fonts, music or runtime SDKs.
