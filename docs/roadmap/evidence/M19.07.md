## Kontrak dan hasil

- Perilaku sebelum: Filter-Id was misused as a bandwidth shaper; no MikroTik-Rate-Limit VSA encoding existed.
- Perilaku sesudah / deliverable:
  - RFC 2865 VSA encode/decode helper in `apps/isp/src/radius_protocol.rs`.
  - Bounded `MikroTik-Rate-Limit` (Vendor-ID 14988, attribute type 8) formatter with RouterOS ordering (rx/upload rate first, tx/download rate second), optional paired burst rate + burst time in seconds.
  - Rejects zero, oversized, half-specified, or malformed rate profiles (fail closed).
  - Access-Accept now carries the VSA; Filter-Id remains a bounded policy classification string (`policy-<connection_type>`), never a bandwidth value.
  - PAP/CHAP and non-MikroTik attributes (Reply-Message, Filter-Id, Framed-IP-Address) unchanged.
  - Golden RouterOS fixtures: `mikrotik_rate_limit_basic.json`, `mikrotik_rate_limit_burst.json`, `mikrotik_rate_limit_oversized.json`.
- File yang diubah:
  - `apps/isp/src/radius_protocol.rs` — VSA encoding/decoding, RouterOS format, bounds
  - `apps/isp/src/main.rs` — Access-Accept carries VSA, Filter-Id policy-only, invalid profiles fail closed
  - `apps/isp/tests/fixtures/` — 3 golden RouterOS rate-limit fixtures + rejection fixture
  - `docs/roadmap/20-isp-rust-go-architecture-aaa.md` (M19.07 acceptance checklist updated)
- Public API/schema/config yang terdampak: Access-Accept now includes VSA attribute 8 (Vendor-ID 14988); Filter-Id is policy classification only.
- Keputusan dan alasan: Per ADR 0019 and M19 roadmap; RouterOS expects rx/upload first then tx/download; fail-closed on invalid profiles ensures no silent shaping misconfiguration.
