## Architectural and governance decisions

- **Entity ownership (`AI1.1`–`AI1.12`):** Reuses `@moonwitness/orm-base`, `orm-organization`, `orm-workflow`, `orm-integration` (SSRF + `MW_AI_*` secret-ref pattern), `orm-knowledge`/`corpus`/`research` (read-only approved APIs), `orm-storage`, and `@moonwitness/jobs` (`SKIP LOCKED`, leases, heartbeats, fencing, outbox, `AbortSignal`). Keeps `@moonwitness/orm-request` (`PurchaseRequest`) unmodified and `@moonwitness/local-ai` isolated for K7.
- **Smallest viable package boundary (`AI1.11`–`AI1.12`):** Rejects unjustified micro-ORM splits; places all durable AI models in one cohesive addon `@moonwitness/orm-ai` (`packages/orm-ai`) and separates execution into `@moonwitness/ai-runtime`, `@moonwitness/ai-mcp` (stateless adapter), and `@moonwitness/ai-evaluation`.
- **Identity & generic API security (`AI1.2`–`AI1.3`, `AI1.14`, `AI1.18`):** Agents bind to a single immutable `Company`, use separately typed `ai.agent` records and optional `role: 'user'` service principals (never `superadmin`/`system`), require `'ai.'` in `INTERNAL_PREFIXES` (`apps/api/src/auth/policy.ts`), and enforce execution-time `ai.capability_grant` checks.
- **Ephemeral data, classification, PCW & memory (`AI1.10`, `AI1.19`–`AI1.24`):** Streaming tokens, scratchpads, raw HTTP payloads, and full transcripts remain outside ORM tables (large blobs in `AttachmentStorage` indexed by `ai.artifact_manifest`). `DataClassificationRouter` blocks cloud routing/fallback for `local_only`/`restricted` payloads. Risk tiers R0–R4, independent PCW verification (`requireDifferentActor: true`), workflow-gated memory/skill promotion, and explicit v1 non-goals are locked in ADR `0007`.
- **Roadmap reconciliation & progress sync (`AI1.26`–`AI1.34`):** Reconciles all proposal IDs in `todo-ai-corporation.md` into `M12.01`–`M12.14` without duplicating or reopening M0–M11 or K0–K9. `ROADMAP.md` + `docs/roadmap/evidence/M12.*.md` remain authoritative for `M12.*`, `tasks.json` tracks DAG dependencies, and `todo-ai-corporation.md` serves as the granular per-checkbox implementation ledger.
