## Implemented

- Added `BugCaseRecord` (`knowledge.bug_case`) and `BugCaseActionOutcomeEvent` (`knowledge.bug_case_event`) in `packages/orm-knowledge/src/bug-case.model.ts`, registered in `manifest.ts` with deny-by-default `ModelAccess` for `base.group_user` and append-only ORM hooks plus SQLite/PostgreSQL triggers on `knowledge_bug_case_events`.
- Reused `@moonwitness/orm-workflow` (`startWorkflow`, `transitionWorkflow`) via `bugCaseWorkflowConfig` (`knowledge.bug_case`: `intake -> triaged -> planned -> action_recorded -> verified_resolved -> reopened -> planned`) with `requireDifferentActor: true` on `verify_outcome`.
- Implemented `intakeBugCase`, `transitionBugCaseWorkflow`, `updateBugCasePublicationStatus`, and `readBugCaseHistory` in `packages/orm-knowledge/src/bug-case-workflow.ts`:
  - Separates `case_state`, `human_approval_status`, `publication_status`, and `resolved_status` so editorial/publication changes cannot mark a case `verified_resolved`, and `verify_outcome` cannot change `publication_status`.
  - Enforces active user/company/membership locking, independent verifier distinct from both the case starter and the action actor, mandatory `mw:evidence:*` reference on `verify_outcome`, slot `#013` `CHILD_SENSITIVE` requirement, and `public_approved` denial on `CHILD_SENSITIVE` records.
  - Enforces idempotency on intake and transitions (`preparePayload` + `verifyPreparedPayloadReplay` + unique `(company_id, bug_case_id, idempotency_key)`), returning exact replays without duplicate rows or side effects and rejecting conflicting replays (`IDEMPOTENCY_CONFLICT`).
- Added 3 Vitest test suites in `packages/orm-knowledge/tests/bug-case-workflow.test.ts` covering end-to-end `intake -> triage -> plan -> record_action -> verify_outcome -> reopen -> replan -> record_action -> verify_outcome`, idempotent replay + conflict rejection, status separation, self-verification denial, SQL append-only trigger protection, cross-company isolation, slot 13 `CHILD_SENSITIVE` protection, and `ModelAccess` denial.
