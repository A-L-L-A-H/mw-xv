## Kontrak dan hasil

- Perilaku sebelum: No ISP network control capability existed in the Go control-plane; ISP orchestration would have required a second control-plane process.
- Perilaku sesudah / deliverable:
  - Added focused, stateless ISP control package `ispcontrol` to `apps/control-plane/ispcontrol/`.
  - Vendor-neutral contracts, read-only policy checks, simulator adapters, bounded request validation, readiness reporting, typed operation errors.
  - Registered explicit ISP routes on existing control-plane mux using existing authenticated and privileged middleware.
  - No SQLite tables, local business persistence, Rust orchestration, ORM HTTP device-control logic, or production device access.
- File yang diubah:
  - `apps/control-plane/ispcontrol/` — new package (contracts, policies, adapters, readiness, errors)
  - `apps/control-plane/isp_routes.go` / `isp_routes_test.go` — route matrix and auth/privilege tests
  - `docs/roadmap/20-isp-rust-go-architecture-aaa.md` (M19.09 acceptance checklist updated)
- Public API/schema/config yang terdampak: New ISP routes under existing control-plane auth boundary.
- Keputusan dan alasan: Per ADR 0019 — Go owns entire ISP network control plane; do not create second process; Rust owns protocol runtimes only. Stateless service posture preserved.
