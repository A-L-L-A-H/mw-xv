## Behavior implemented

- `apps/isp/src/main.rs` `process_accounting_request` writes accounting data before constructing an `Accounting-Response`. Failure of the durable write, including NAS lookup failure, returns `None` (no ACK) so the NAS retransmits; an `accounting_acks_withheld` atomic counter is exposed as `moonwitness_isp_accounting_acks_withheld_total` for bounded diagnostics.
- Test `accounting_request_with_db_failure_does_not_ack` forces a pool failure and asserts no response and a withheld-ACK metric increment.
- Test `accounting_retransmission_persists_once_after_recovery` closes the pool, then reopens it and retransmits the same request, asserting a single persisted session row.
