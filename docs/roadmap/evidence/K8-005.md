## Implemented

- Added `apps/api/src/routes/bug-case.routes.ts` mounted in `apps/api/src/app.ts`:
  - `POST /api/research/bug-cases`: enforces authentication (`401`), company context (`403`), fail-closed `evaluateChildProtectionAndPublicationGate` (`K6-004`) blocking `CHILD_SENSITIVE` / slot `#013` / minor PII submissions until safeguarding escalation is approved, and idempotent `intakeBugCase` (`K6-003`) starting at `intake` / `unreviewed` / `unpublished` / `unresolved`.
  - `POST /api/research/bug-cases/:caseId/transitions`: enforces role/company scoping and idempotency across `triage`, `plan`, `record_action`, `reopen`, and `replan`, excluding `verify_outcome`.
  - `POST /api/research/bug-cases/:caseId/verify-outcome`: restricted to `superadmin` + active company membership, invoking `verifyBugCaseOutcomeWithEvidence` (`K6-005`) with `K3-002` evidence selector, passing test proof, and fail-closed default null resolver unless injected.
  - `GET /api/research/bug-cases/:caseId`: returns `Cache-Control: private, no-store` case status for active company members, concealing `CHILD_SENSITIVE` cases from ordinary `user` role and denying cross-company reads (`403`/`404`).
- Added 2 Vitest route suites in `apps/api/tests/bug-case.routes.test.ts` covering `401` unauthenticated denial, slot `#013` / `CHILD_SENSITIVE` denial, minor-PII screening, exact replay vs `409` conflict, full transition + independent outcome verification, self-verification `403` denial, and cross-company isolation.
