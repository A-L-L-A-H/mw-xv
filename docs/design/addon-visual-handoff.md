# Addon visual handoff

This guide connects domain add-ons to presentation without coupling backend packages to artwork or UI. The canonical contract and current domain audits live in [`ADDON_ASSET_MATRIX.md`](../../MWXV_ULTRA_COMPLETE_VISUAL_UNIVERSE_AUTONOMOUS_PACK/ADDON_ASSET_MATRIX.md) and [`evidence/domains/`](../../MWXV_ULTRA_COMPLETE_VISUAL_UNIVERSE_AUTONOMOUS_PACK/evidence/domains/). The asset path in `packages/assets/manifest.json` is the stable visual reference; license and creator provenance is in `packages/assets/licenses.json`.

## Ownership and resolution

1. ORM add-ons own models, view metadata, permissions, and lifecycle semantics. They must not import UI, assets, browser APIs, or artwork.
2. API handlers enforce the domain's authorization and visibility rules. They return records/state; they do not choose visual assets.
3. Board maps real model and state identifiers to shared UI components and canonical assets. `apps/board/src/lib/models.ts` is the generic model icon resolver; domain panels may map a verified model/state to a typed icon or existing composition.
4. Shared components come from explicit `@moonwitness/ui` subpaths. Static media comes from explicit `@moonwitness/assets` exports or the manifest-driven public asset pipeline. No private `dist` path or copied domain asset is permitted.
5. The UI Catalog may show clearly labelled design examples for missing production consumers. Such fixtures must never be presented as production records.

## Adding or changing a mapping

- Confirm the model, route, API response and effective permission in source first. A manifest menu is not proof that a route is available to every user.
- Reuse an existing canonical asset by manifest path and its existing license record. If a new asset is necessary, register provenance before using it and keep text, controls, identity and changing data in HTML.
- Make loading, empty, error/unavailable and access-denied states separately understandable. Do not turn an unavailable response into a zero count or empty result.
- Add focused component/browser coverage for the actual permission and recovery path. Label catalog-only data as an example and include an explicit note when no production consumer exists.
- Keep ORM/API changes presentation-agnostic. Verify boundaries with `pnpm board:ui:check`, assets with `pnpm test:assets`, shared consumers with `pnpm test:ui`, and visual/accessibility coverage with `pnpm test:ui-catalog` plus the relevant Board E2E matrix.
